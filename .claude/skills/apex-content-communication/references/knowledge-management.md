# Knowledge Management

## Scope
Capturing, organizing, and surfacing institutional knowledge: wikis, docs, discoverability, and maintenance.

## Core principles
- Knowledge dispersed in Slack or email is lost; centralized knowledge (wikis, searchable docs) compounds over time.
- The cost of writing is low; the cost of maintaining outdated docs is high (people trust them until they don't). Deprecate clearly or commit to keeping it current.
- Discoverability matters as much as presence; a document hidden 5 clicks deep is useless. Search, tagging, and linked navigation must work.
- Ownership (who maintains this?) prevents abandonment. Assign an owner and review cycle (quarterly, monthly).
- Access (who can read/write?) balances openness and quality. Public wikis welcome contributions; gatekeeping ensures review but slows sharing.

## Apex practices
- Use a hybrid structure: living docs (updated frequently, open-ended) for processes; archived docs (versioned, stable) for decisions/standards.
- Implement a "last updated" timestamp and "needs review" flag; signals that docs are actively maintained.
- Link aggressively: related docs, glossary, external references. Readers follow links more readily than search.
- Periodically audit: which docs get views, which are orphaned? Delete or archive stale docs; clarity trumps archives.

## Pitfalls
- "Write it once, it's done" mentality; knowledge rots as context changes, products evolve, or tools update.
- Mixing evergreen knowledge with temporary updates; use separate sections or versions.
- Centralizing knowledge without discoverability tools (full-text search, tagging); it's invisible.

## Tools & references
Confluence / Notion / Obsidian (platforms), Docusaurus / MkDocs (doc sites), semantic wiki tagging, knowledge base analytics.
