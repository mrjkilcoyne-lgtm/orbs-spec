# Tutorials & How-Tos

## Scope
Step-by-step guides for learning and accomplishing tasks: clarity, completeness, testing, and structure that assumes zero context.

## Core principles
- A tutorial teaches concepts; a how-to completes a task. Tutorials are longer, build foundations, and explain why. How-tos are short, focused on the outcome, and assume some knowledge.
- Every step must be actionable: "press the blue button" beats "configure the settings." Include screenshots or exact paths.
- Assume nothing: explain every term, don't skip "obvious" steps, and show what success looks like (screenshot of correct output).
- Test your tutorial by following it cold with someone new; if they get stuck, the instructions are incomplete. Iterate until someone follows it without asking questions.
- One task per how-to; if your guide needs an outline with 5 sections, split it into 5 separate how-tos that interlink.

## Apex practices
- Start with prerequisites (what the reader already should know), tools needed, and time required; set expectations upfront.
- Use the imperative voice ("Click here," "Enter your API key") not passive ("The button can be clicked").
- Provide a "troubleshooting" section with common mistakes and fixes; users will make them and need help unsticking.
- Include a "next steps" section linking to related tutorials or advanced material; don't leave readers stranded at the end.

## Pitfalls
- Bloating with unnecessary information; a how-to on "Deploy to Heroku" doesn't need a Git tutorial, link instead.
- Skipping steps because they seem obvious to the author; users are new and will miss them.
- Providing only success paths; what happens if the command fails? Prepare users for common error messages.

## Tools & references
Usability testing for documentation, VidYard or Loom for screencasts, step-by-step walkthroughs, numbered lists (not bullets), verification steps.
