# Style Guides

## Scope
Documenting voice, terminology, formatting, and tone for consistency across writers and time.

## Core principles
- A style guide codifies decisions (capitalization, punctuation, terminology) so writers don't re-decide them; consistency feels professional without effort.
- Voice and tone are distinct: voice is personality (warm, authoritative, playful), tone is mood within voice (urgent, casual, formal). Document both.
- Usage entries (how to use a term, common mistakes) prevent drift; "API" vs "api" or "customer" vs "user" should be decided once.
- The best style guides are concise and example-driven; a 200-page manual nobody reads is useless.
- Style guides evolve; document how and when you update them so the team stays in sync.

## Apex practices
- Structure as: Brand voice & tone → Grammar & punctuation → Word usage & terminology → Formatting & visual style → Examples and anti-patterns.
- Use tables (not prose) for quick reference (capitalization rules, punctuation conventions).
- Include a glossary of terms unique to your domain or product.
- Create checklists for common docs (release notes, API docs) so writers follow the format without reading the full guide.

## Pitfalls
- Adopting a famous guide wholesale (AP, Chicago, APA) without adjusting for your voice; style guides should reflect your brand.
- Over-prescribing rules that don't matter (Oxford comma preference is fine; requiring it everywhere is pedantry).
- Failing to enforce or update the guide; it becomes a desk reference nobody uses.

## Tools & references
Chicago Manual of Style, AP Stylebook, Mailchimp / Microsoft / Google brand voice guides (public examples), Living styleguide (version-controlled docs).
