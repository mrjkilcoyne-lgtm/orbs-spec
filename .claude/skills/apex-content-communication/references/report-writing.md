# Report Writing

## Scope
Structuring investigative or analytical documents: clarity of findings, supporting evidence, and actionable recommendations.

## Core principles
- A report is not a journal; it's an instrument to inform a decision. Every section should answer "why does the reader need this now?"
- Front-load the most important information: executive summary, key findings, then supporting detail. Readers skim; assume they stop after the summary.
- Evidence hierarchy: start with primary evidence (data, direct quotes), then secondary (literature, expert opinion). Distinguish signal from noise.
- Recommendations must be specific and prioritized: "improve efficiency" is vague; "reduce API latency by 200ms by caching results (estimated ROI: $50k/year, timeline: 6 weeks)" is actionable.
- Visual data (charts, tables, infographics) should stand alone; a reader skipping paragraphs should still grasp your meaning from visuals and captions.

## Apex practices
- Structure as: Summary → Context → Findings → Analysis → Recommendations → Implementation. Each section is self-contained with clear headings.
- Use a findings-first format: lead each section with the insight (bold or callout), then support with evidence.
- Include a table of contents and internal links; readers navigate by searching and jumping, not sequential reading.
- Appendices hold detail (methodology, raw data, literature cited) separate from narrative; the main body stays focused.

## Pitfalls
- Burying the lede: recommendations at the end of 50 pages guarantee nobody acts on them. Put them front and center.
- Mixing analysis with opinion; distinguish "our data shows" from "we believe," and cite both.
- Over-producing without purpose; a 200-slide deck is worse than a 10-page report if the report lands the insight.

## Tools & references
Pyramid Principle (Barbara Minto), Executive Summary standards (business school template), data storytelling (Cole Nussbaumer Knaflic).
