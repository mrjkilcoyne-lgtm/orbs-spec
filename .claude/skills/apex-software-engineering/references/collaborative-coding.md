# Collaborative Coding

## Scope
Producing code together: pair programming, mob/ensemble sessions, async collaboration across time zones.

## Core principles
- Pairing trades throughput for defect rate, knowledge spread, and onboarding speed — use it where those matter.
- Driver/navigator only works when the navigator thinks ahead; two people watching one type is not pairing.
- Rotate pairs and mob roles on a timer; stagnant pairs converge to solo-with-witness.
- Async collaboration runs on artifacts: small PRs, written context, recorded decisions.
- Psychological safety is load-bearing — the junior's "why?" catches the senior's autopilot mistake.

## Apex practices
- Ping-pong pairing: one writes the failing test, the other makes it pass, swap.
- Timebox mob rotation (5-10 min) with strong-style ("ideas go through someone else's hands").
- For remote pairing, shared control tooling and frequent role swaps beat screen-watching.
- Reserve pairing for the gnarly 20% (design, debugging, onboarding); async for the routine 80%.

## Pitfalls
- Mandatory 100% pairing that burns people out and hides individual growth needs.
- The senior grabbing the keyboard "to speed things up."
- Decisions made in a pairing session that never get written down for the rest of the team.

## Tools & references
"The Mob Programming Guidebook," tuple/Live Share tooling, strong-style pairing (Llewellyn Falco).
