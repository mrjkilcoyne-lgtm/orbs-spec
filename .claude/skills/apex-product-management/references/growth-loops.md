# Growth Loops

## Scope
Designing self-reinforcing acquisition and engagement systems: viral, content, paid, and sales loops where output feeds back into input.

## Core principles
- Loops beat funnels because funnels are linear and decay: a funnel needs constant top-up spend; a loop reinvests its own output (new user → creates content/invites → attracts new user), compounding instead of leaking (the Reforge loops framing).
- Every loop has a quantifiable cycle: viral factor K = invites per user × conversion rate, with cycle time — K=0.5 with a 2-day cycle can outgrow K=0.7 with a 30-day cycle over a quarter; measure both, not just K.
- Loops must be native to the product's usage, not bolted on: Dropbox referrals worked because storage-for-invites matched the product's value; a generic "refer a friend for $10" on a B2B compliance tool fights the product's physics.
- The main loop types are viral (user-invites-user), UGC/SEO content (user output becomes indexed acquisition surface — Pinterest, Glassdoor, Stack Overflow), paid (revenue → ad spend → users → revenue, viable only when payback < cash cycle), and sales-led (revenue funds reps); most durable companies run one dominant loop plus one support loop.
- Loops saturate: each loop has a ceiling (audience exhaustion, keyword saturation, rising CAC), so the growth model needs the NEXT loop identified before the current one flattens — the S-curve stacking problem.

## Apex practices
- Draw the loop explicitly (nodes, conversion rates, cycle time) and identify the constraining step; improving a non-bottleneck step of the loop produces nothing, exactly like theory-of-constraints in manufacturing.
- Instrument loop metrics separately from funnel metrics: invites sent per active user, invite→signup rate, content pieces indexed per cohort, time-to-loop-completion — funnel dashboards make loops invisible.
- Prototype incentive structures on both sides of the loop (giver AND receiver get value — Dropbox gave storage to both; PayPal paid both) since one-sided incentives halve conversion.
- Pressure-test for quality decay: loops that reward volume (invites, posts) degrade quality as they scale; build quality gates in before the spam dynamic, not after the brand damage.

## Pitfalls
- Chasing K>1 "true virality" — almost nothing sustains it; the realistic goal is a viral assist that lowers blended CAC, layered on a retention-sound core.
- Growth-hacking a leaky bucket: pouring loop-driven signups onto a product with 10% week-4 retention just amortizes churn faster.
- Copying another company's loop without its precondition (UGC-SEO requires content with durable search demand; invite loops require multi-player value).
