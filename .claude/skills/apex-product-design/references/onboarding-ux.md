# Onboarding UX

## Scope
First-run experience: progressive disclosure, feature discovery, tutorials, and getting users to core value quickly.

## Core principles
- The first 30 seconds are critical; show the core value before asking for login or setup — delay payoff and users leave.
- Progressive disclosure reveals features as users need them, not all at once; showing 20 options on launch overwhelms.
- Tutorials should be skippable and contextual; modal dialogs that interrupt are frustrating (users skip them), but hint text at the right moment helps.
- Onboarding flows should feel like a product tour (delightful) not a compliance exercise (painful); tone matters.
- Metrics: measure signup completion rates, feature discovery (do users find features without tutorials?), and time to core action (how long to first valuable output?).

## Apex practices
- Test onboarding with new users (not team members who know the product); watch where they get stuck or confused.
- Implement contextual hints (tooltips, empty state prompts) instead of modal tutorials; they're less disruptive and more targeted.
- Create separate onboarding for different user types (new vs existing, web vs mobile, free vs paid) — one size doesn't fit all.
- Measure onboarding effectiveness: track completion rates, time-to-value, and feature adoption post-onboarding.

## Pitfalls
- Mandatory tutorials that users skip (and then get lost); make tutorials skippable.
- Onboarding flow that diverges from the main app (tutorial looks different from real UI); keep onboarding consistent with the app.
- Assuming users read onboarding; most skip it — focus on intuitive UI and contextual help.

## Tools & references
Appcues, Pendo, Intercom for onboarding implementation, Hotjar for heat map analysis, user research on first-run experience; "Jobs to be Done" interviews for understanding user motivation.
