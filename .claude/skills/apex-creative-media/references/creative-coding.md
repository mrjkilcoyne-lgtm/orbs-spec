# Creative Coding

## Scope
Writing code for artistic intent: real-time graphics, interactive installations, sonification, and using programming as a medium for expression, not just utility.

## Core principles
- Code is a canvas: in creative coding, readability and performance are secondary to visual and interactive results; often the constraints (limited color palette, pixel grid, computational budget) are part of the aesthetic.
- Feedback loops (interactive real-time response) are essential: sketching ideas visually through code is much faster than describing them verbally.
- Libraries and frameworks (GLSL shaders, WebGL, Cinder, openFrameworks) are tools for speed; knowing them lets you focus on concept instead of plumbing.
- Iteration in creative coding is non-linear: you explore the space of possibility with parameters and see what emerges; it's design through play, not design-then-implement.
- Abstraction (extracting patterns into functions, classes) scales creative ideas; a simple abstraction applied recursively or to many instances creates complexity from simplicity.

## Apex practices
- Start with a constraint (monochrome, 64x64 pixels, sine-wave only) and iterate within it; constraints are creative fuel, not limitations.
- Use noise and randomness with structure (seeds, ranges, curves) for organic-feeling results; pure randomness is boring.
- Prototype in a live-coding environment (Hydra, Shadertoy, Processing) to see results immediately; the feedback loop is creative oxygen.
- Combine code with other media (video, audio, physical input) to create hybrid pieces; code alone is technical, but code + sound + interaction is art.

## Pitfalls
- Optimizing prematurely for performance before establishing visual concept; profile and optimize only after beauty is decided.
- Treating code as invisible infrastructure instead of part of the art; sometimes showing the algorithm or code itself is the work.
- Ignoring UI/UX in interactive pieces; if an audience can't interact intuitively, they won't engage.

## Tools & references
Processing, p5.js, Hydra, Shadertoy, Cinder, openFrameworks, GLSL, Perlin/Simplex noise, Vera Molnár (early generative art), Ben Laposky (Elektron instruments), Reas/McWilliams' books.
