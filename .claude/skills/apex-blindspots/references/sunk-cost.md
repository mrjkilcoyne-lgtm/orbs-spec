# Sunk Cost

## Scope
Continuing a course because of what's already spent — the rewrite that must ship because it's late, the feature kept because it was hard, the approach defended because it's yours.

## Core principles
- Spent resources are gone under every branch of the decision tree: only future costs and future value differ between options — the past is a constant, and constants don't affect which choice is best.
- The bias is emotionally load-bearing: abandoning a project feels like declaring the past effort worthless, so the mind reframes quitting as failure and persisting as grit — but grit toward a dead end is just slower failure.
- Escalation of commitment compounds it publicly: having defended the decision, each new doubt threatens face, so evidence standards rise for quitting and fall for continuing (the Concorde kept flying at a loss for decades — the fallacy's namesake).
- Sunk cost hides in code as attachment: the clever module that no longer fits, the framework migration half-done for two years — "we've come too far" is the tell.
- The inverse trap exists too: over-correcting into premature abandonment at the first difficulty; the discipline is fresh-eyes evaluation, not reflexive quitting.

## Detection tests
- If I were starting today with current knowledge and zero history, would I choose this path?
- Is my main argument for continuing phrased in past tense ("we've already...")?
- What would I advise someone else in exactly this position?

## Countermeasures
- Schedule kill-or-commit reviews at pre-set milestones with criteria written before work began — deciding the exit test in advance removes the face-saving negotiation.
- Separate the decider from the historical champion where stakes are high: fresh eyes don't owe the past anything.
- Reframe the ledger: value already extracted (learning, validated dead-ends) is banked regardless; quitting doesn't erase it.

## Tools & references
Arkes & Blumer's sunk-cost studies, "The Art of Quitting"/"Quit" (Duke), stage-gate processes, kill criteria in project charters.
