# Anchoring

## Scope
The first number, framing, or design in the room dragging all subsequent judgment toward itself — in estimates, negotiations, reviews, and iteration.

## Core principles
- Anchors work even when known to be arbitrary (the wheel-of-fortune experiments): awareness alone does not immunize; only structural countermeasures do.
- The first estimate in an estimation meeting sets the range: whoever speaks first anchors the room, which is why planning poker reveals simultaneously.
- Anchoring compounds in iteration: the first draft becomes the reference against which changes are judged as "too different," so the design space collapses to the first idea's neighborhood — v1 anchors v2 anchors v3.
- Framing is an anchor without a number: "how do we make onboarding shorter?" anchors on shortening; the unanchored question is "why do users leave during onboarding?"
- Old numbers anchor new realities: last year's budget, the legacy system's latency, the original scope — inherited baselines get treated as natural laws instead of historical accidents.

## Detection tests
- What was the first number/design/framing introduced, and how far has anything moved from it?
- If I'd encountered this problem with no prior figure, what would I estimate cold?
- Are we optimizing within a frame nobody chose deliberately?

## Countermeasures
- Estimate independently before revealing (silent writing, then share) — in groups and in your own head (form your number before reading theirs).
- Generate 3 genuinely different candidates before critiquing any (the atelier's divergence phase is anti-anchoring machinery).
- Re-derive inherited baselines occasionally from first principles: "what would this budget/deadline/threshold be if set fresh today?"

## Tools & references
Tversky & Kahneman's anchoring studies, planning poker / wideband Delphi, "Never Split the Difference" (Voss) for negotiation anchors, zero-based budgeting.
