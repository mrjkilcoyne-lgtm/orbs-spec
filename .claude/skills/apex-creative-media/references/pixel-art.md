# Pixel Art

## Scope
Creating constrained visual art with low resolution and limited color palettes: pixels as intentional units, anti-aliasing rejection, and aesthetic embracing technical limitations.

## Core principles
- Pixels are visible units: anti-aliasing (smoothing edges) destroys pixel art; each pixel is a choice, and the grid is aesthetic, not accidental.
- Color palette constraint (16 colors, 32 colors, 64 colors) forces intentional color choices and visual unity; a restricted palette reads as cohesive.
- Dithering (mixing colors with patterns to suggest intermediate hues) is an art form; Floyd-Steinberg dithering is technical, but ordered dithering and hand-dithering are tools.
- Aseprite (de facto pixel art tool) is optimized for pixel-perfect animation, layers, and indexed color; it's not Photoshop, and that's the point.
- Small scale (16x16, 32x32 sprites) forces clarity: every pixel matters, silhouettes must be readable, animation must be readable at glance.

## Apex practices
- Start with silhouette: rough out shape at actual size in a single color, then refine; if the silhouette isn't clear, detail won't save it.
- Animate on paper or in Aseprite with onion-skin (tracing previous frames) so you see motion continuity; pixel animation is pose-to-pose.
- Limit color palette to 16–32 colors; create a cohesive palette, then mix colors intentionally (avoiding muddy gradients).
- Study existing pixel art (classic games, contemporary indie): artists like Sable, Hyper Light Drifter, Hollow Knight show mastery within constraints.

## Pitfalls
- Assuming pixel art is simple because resolution is low; it requires more design discipline, not less.
- Using anti-aliasing or gradients; they destroy pixel aesthetic.
- Scaling pixel art incorrectly (integer scaling required: 2x, 3x, 4x, not 2.5x or 1.5x).

## Tools & references
Aseprite (industry standard, $$ but worth it), Piskel (free, web-based), GraphicsGale, GrafxKid (animation tutorials), classic games (Castlevania, Metroid, Final Fantasy).
